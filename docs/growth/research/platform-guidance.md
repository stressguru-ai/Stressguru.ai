# Platform guidance verified October 24, 2026

Google states that its existing SEO fundamentals apply to AI Overviews and AI Mode. Indexed, snippet-eligible pages are necessary; no special AI schema or machine-readable file is required. Important content must be textual, internal links useful, and structured data consistent with visible content. Search Console includes AI-feature traffic within Web search reporting, so that aggregate is not a separately measured AI citation metric.[1]

OpenAI documents independent controls for OAI-SearchBot and GPTBot. OAI-SearchBot is search discovery; GPTBot can collect training material. ChatGPT-User performs user-initiated retrieval and is not an automatic search crawler. Allowing training is not a prerequisite for search appearance.[2]

Anthropic separately documents Claude-SearchBot for search, Claude-User for user-directed retrieval, and ClaudeBot for potential model training. All three are distinct controls. The site's existing training allow choice is preserved under the approved policy.[3]

Ploy's public documentation supports reusable scheduled Ploybooks, ongoing projects, analytics, experiments, and agent workflows. The useful pattern for StressGuru is persistent shared context plus research, measured prioritization, bounded implementation, and review. Ploy's hosting, visitor identification, outbound automation, and database architecture are not adopted. Promotional examples on Ploy's site do not prove a particular ranking mechanism or guarantee citations.[4] [5]

The existing StressGuru llms resources are retained as optional public reference documents, not advertised as ranking shortcuts. Crawlability, useful content, accurate attribution, and measured user actions take priority. Initial HTML checks are not a substitute for rendered parity checks or field Core Web Vitals.
